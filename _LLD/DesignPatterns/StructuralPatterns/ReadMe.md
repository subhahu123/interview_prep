# Structural Design Patterns – Comparison Table

| Pattern     | Focus                                | Use When                                                  | Real-World Example                                      |
|-------------|---------------------------------------|------------------------------------------------------------|----------------------------------------------------------|
| **Adapter**     | Converts one interface to another     | You need to make incompatible interfaces work together     | Power plug adapter, legacy API wrapper                   |
| **Bridge**      | Decouple abstraction from implementation | You want to vary abstraction and implementation independently | Remote & Devices, UI control and rendering backends      |
| **Composite**   | Tree structures of objects            | You want to treat part-whole hierarchies uniformly         | Folders & Files, UI components like containers and buttons |
| **Decorator**   | Add responsibilities dynamically      | You want to enhance object behavior without changing class | Coffee with milk/sugar, adding scrollbars to UI component|
| **Facade**      | Simplify complex subsystem            | You want to provide a unified interface to a set of classes | Computer startup sequence, Hotel reception desk          |
| **Flyweight**   | Share common state between objects    | You need to manage large numbers of similar objects        | Character glyphs in text editors, trees in game world    |
| **Proxy**       | Control access to an object           | You want lazy loading, access control, or logging          | Virtual proxy for videos, protection proxy for admin-only APIs |
